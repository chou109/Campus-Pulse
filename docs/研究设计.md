# 校园健身社交激励系统：研究设计与实现说明

## 一、研究定位

研究方向为“运动健康与社交激励的交叉应用”，目标是验证：运动数据反馈、轻量社交比较、集体挑战和成就反馈能否降低大学生开始运动与持续运动的成本。

## 二、核心闭环

```text
前台定位/演示数据
  → 运动记录（距离、时长、配速、轨迹）
  → 个人趋势与周榜/月榜
  → 打卡、挑战、勋章、同伴反馈
  → 下一次运动意愿与连续打卡
```

## 三、模块设计

| 模块 | 原型实现 | 研究关注点 |
| --- | --- | --- |
| 运动记录 | `pages/run`，演示/真实定位双模式 | 数据采集可用性、授权接受度 |
| 数据可视化 | 首页周趋势、个人累计数据 | 反馈是否易理解、是否形成目标感 |
| 榜单 | 周榜/月榜、个人高亮 | 社会比较的激励与压力边界 |
| 活动挑战 | 进度、奖励、加入状态 | 集体目标和任务完成率 |
| 勋章体系 | 已解锁/未解锁勋章墙 | 阶段性成就对坚持性的影响 |
| 隐私控制 | 公开榜单、好友可见、提醒 | 用户对位置和社交数据的控制感 |

## 四、建议的数据模型

### `运动记录`

- `id`
- `user_id`
- `started_at` / `ended_at`
- `distance_km`
- `duration_seconds`
- `avg_pace_seconds`
- `calories`
- `route_points`（生产环境应考虑抽样、模糊化和保存期限）
- `visibility`
- `source`（demo / location）

### `挑战`

- `id`
- `title`
- `rule_type`
- `target_value`
- `starts_at` / `ends_at`
- `reward_medal`
- `status`

### `挑战参与`

- `challenge_id`
- `user_id`
- `progress`
- `completed_at`

### `勋章`

- `id`
- `code`
- `name`
- `unlock_rule`
- `unlocked_at`

## 五、推荐的服务端边界

客户端只提交经过采集的原始或候选数据；服务端负责：

1. 从登录态确定 `user_id`，不接受客户端任意指定；
2. 校验运动记录长度、时间、点位跳跃和重复提交；
3. 计算排行榜、挑战进度和勋章解锁；
4. 对公开展示做昵称、头像和轨迹脱敏；
5. 提供删除记录、撤回分享和隐私设置接口；
6. 记录审计信息，但不在日志里写入完整轨迹和敏感身份信息。

## 六、评估方案

### 功能指标

- 记录成功率、定位失败提示覆盖率、结束打卡成功率；
- 首页、榜单、活动、勋章页面的加载与空态表现；
- 重复提交、越权访问、异常点位和撤回分享测试。

### 用户体验指标

可使用 5 点量表收集：

- 运动数据是否容易理解；
- 榜单是否产生适度激励；
- 挑战是否提高了参与意愿；
- 勋章是否让用户愿意再次运动；
- 隐私控制是否清晰、可控。

### 行为指标

在取得授权并完成匿名化后，可比较：

- 首次运动到第二次运动的转化率；
- 7 日连续打卡率；
- 挑战加入率与完成率；
- 分享后再次运动率；
- 榜单曝光与运动频次的相关性。

## 七、测试重点

1. 演示模式无需定位即可完整走通；
2. 真实定位拒绝、失败、低精度、跳点和停止记录；
3. 运动记录为空、重复点击结束、切换页面和中断恢复；
4. 周榜/月榜切换、本人高亮和空数据；
5. 活动加入、重复加入、进度显示和奖励文案；
6. 隐私开关和位置授权说明；
7. 小屏设备的卡片、图表和底部导航布局。
