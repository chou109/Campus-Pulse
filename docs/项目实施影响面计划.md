## 2. 当前状态

### 2.1 已验证事实

当前目录已经存在一个原生微信小程序原型，主要文件包括：

- `app.js`、`app.json`、`app.wxss`；
- `pages/index/`：首页、本周数据和最近动态；
- `pages/run/`：运动记录、演示定位和前台定位基础逻辑；
- `pages/rank/`：周榜/月榜展示；

当前原型已具备：

- 前台定位模式的基础调用逻辑；
- 里程、时长、配速和热量展示；

- 周榜/月榜页面；

- 多用户社交动态；
- 生产环境隐私协议和数据删除闭环；

### 2.2 当前工作假设

以下内容是本计划的建议方案，不视为已确认事实：

- 第一阶段先完成研究展示版，而不是直接建设生产系统；
- 第一阶段继续使用演示数据和本地存储；
- 真实定位只做前台定位，不做后台持续定位；

- 当前原型作为后续实现的基线，不推倒重做。

## 3. 第一阶段目标

第一阶段目标是完成一个可在微信开发者工具中运行、能够完整演示核心研究闭环的原型：

```text
运动记录 → 数据统计 → 趋势/榜单 → 挑战 → 勋章 → 持续运动激励
```

### 3.1 第一阶段包含

1. 完善首页运动数据展示；
2. 完善开始、暂停、继续和结束运动流程；
3. 完善演示模式，使无定位权限时也能完整演示；
4. 完善前台定位的授权、失败和停止记录状态；
5. 展示运动距离、时长、配速、热量和轨迹；
6. 完善周趋势和月度数据展示；
7. 完善周榜/月榜和个人排名高亮；
8. 完善线上挑战加入、进度和完成状态；
9. 完善勋章墙和解锁状态；
10. 增加运动记录删除或清空入口；
11. 增加位置数据和运动数据用途提示；
12. 完成第一阶段功能测试和页面验收。

### 3.2 第一阶段不包含

- 微信真实登录；
- 服务端 API 和真实数据库；
- 真实用户之间的社交动态同步；
- 后台持续定位；
- 真实通知、支付、积分或奖品；
- 生产环境部署；
- 管理后台；
- 复杂反作弊系统；
- 未经授权的云资源、Secret 或服务器配置。

## 4.2 数据影响

第一阶段预计只影响本地演示数据：

```text
本地 storage
    ├── 运动记录
    ├── 挑战状态
    └── 页面展示状态
```

### 数据字段

运动记录至少包含：

- 日期；
- 开始和结束时间；
- 运动时长；
- 距离；
- 平均配速；
- 热量；
- 轨迹点；
- 数据来源：`demo` 或 `location`。

### 数据安全边界

- 不保存真实用户身份信息；
- 不提交真实位置轨迹；
- 不把日志、截图或导出数据提交到代码仓库；
- 默认使用演示模式；
- 真实定位数据仅在用户主动授权并开始记录后采集；
- 用户可以停止运动记录；
- 用户可以删除本地运动记录。

## 4.4 UI 影响

第一阶段会涉及以下页面交互：

- 首页：新增或调整统计、趋势和动态空态；
- 运动页：开始、暂停、继续、结束、授权失败和安全提示；
- 榜单页：周榜/月榜切换、本人高亮、空数据；

UI 需要覆盖：

- 定位失败；
- 正在记录；
- 暂停记录；
- 完成运动；
- 空榜单；
- 挑战未加入；
- 挑战已完成；
- 数据删除确认。

## 5. 核心数据流

### 5.1 演示模式

```text
用户点击开始
    ↓
生成演示轨迹点
    ↓
计算距离、时长、配速和热量
    ↓
用户结束运动
    ↓
写入本地 storage
    ↓
首页、趋势和个人中心刷新
```

### 5.2 前台定位模式

```text
用户主动授权定位
    ↓
用户点击开始
    ↓
前台定时获取位置
    ↓
过滤无效或异常点位
    ↓
计算运动数据并绘制轨迹
    ↓
用户主动结束
    ↓
写入本地 storage
```

### 5.3 后续真实系统数据流

真实系统暂不实施，后续应采用：

```text
微信登录态
    ↓
服务端确认 user_id
    ↓
服务端校验运动数据
    ↓
数据库保存记录
    ↓
服务端计算榜单、挑战和勋章
    ↓
客户端读取结果
```

客户端不能直接决定：

- 用户身份；
- 运动记录归属；
- 榜单名次；
- 挑战完成状态；
- 勋章解锁状态；
- 奖励发放结果。

## 6. 研究影响范围

本项目不只是页面开发，还需要支持后续研究分析。

### 6.1 研究问题

建议围绕以下问题展开：

1. 运动数据的即时反馈是否能够增强用户目标感；
2. 周榜/月榜是否会形成适度的同伴激励；
3. 线上挑战是否能够提高运动参与意愿；
4. 勋章成就是否能够促进连续打卡；
5. 用户是否能够理解并接受位置数据和社交可见性设置。

### 6.2 可观测指标

- 首次运动完成率；
- 再次运动率；
- 连续打卡天数；
- 挑战加入率；
- 挑战完成率；
- 榜单访问次数；
- 勋章查看次数；
- 打卡分享意愿；
- 定位授权拒绝率；
- 用户对隐私提示的理解程度。

### 6.3 研究限制

第一阶段使用演示数据和本地存储，只能验证：

- 页面流程；
- 交互可用性；
- 激励机制的产品表达；
- 初步用户体验。

不能仅凭第一阶段原型证明社交激励对真实运动坚持行为具有因果影响。

## 7. 安全与隐私风险

| 风险 | 影响 | 第一阶段措施 |
| --- | --- | --- |
| 位置权限被拒绝 | 无法记录真实轨迹 | 提供演示模式和明确提示 |
| 位置跳点 | 距离和配速异常 | 过滤异常点，保留错误提示 |
| 客户端伪造里程 | 榜单不可信 | 第一阶段仅作演示；第二阶段由服务端计算 |
| 轨迹泄露 | 暴露用户活动范围 | 不公开完整轨迹，生产环境需要模糊化 |
| 重复提交 | 数据重复、榜单失真 | 增加结束按钮防重复和记录去重 |
| 过度运动 | 可能造成身体风险 | 增加安全提示，不提供医疗判断 |
| 隐私设置不清晰 | 用户无法控制分享 | 明确可见范围和删除入口 |
| 测试数据泄露 | 暴露个人信息 | 使用演示数据并脱敏 |
