## 3. R2 AI 代理安全补强：自动化通过，DevTools 兼容待验收

`dev/ai-proxy.js` 保持 loopback-only 和既有数据白名单/模型 schema/超时/客户端降级，增加：

- Host 必须是 `127.0.0.1` 或 `localhost`，并匹配当前监听端口；不接受伪装域名；
- 无 Origin 的本机请求继续兼容；有 Origin 时只允许规范化后的 HTTP/HTTPS localhost 来源；拒绝外部、`null`、伪装后缀及无效 Origin；
- 对允许的 Origin 精确回显 `Access-Control-Allow-Origin`，加 `Vary: Origin`，不返回通配 CORS；拒绝请求不调用上游；
- 单进程 1 个在途模型请求，滚动 60 秒最多启动 5 个有效模型请求；拒绝请求返回 429/`Retry-After`；预检、health、拒绝来源和无效输入不耗额度；上游成功/失败路径释放并发槽。

新增 `tests/ai-proxy-security.test.js`，使用合成密钥、动态本机端口和模拟上游；10 项安全测试全部通过，包括 Origin/Host、无 Origin 兼容、预检、限流、并发和失败释放。没有一项测试调用真实模型。

兼容限制：尚未在本机微信开发者工具中观察实际 `wx.request` 的 Origin/Host。历史 CLI 尝试提示开发者工具 Service Port 关闭；本轮按计划不调整工具安全设置，所以小程序实际请求头仍待 GUI 验收。若真实工具发送非本机 Origin，不应直接放宽为通配，需先记录来源并由 Owner 评估。
