# Campus Pulse 本地运营后台实施记录

> 阶段：Stage C1，本地 Web Admin + 配置 API
> 日期：2026-09-30
> 状态：首轮实现与验收完成，准备中文提交推送。

## 1. 方案

按 Owner 澄清，“多端”是指用户微信小程序和运营后台两个工作端，不指学生账号跨手机同步。本阶段实现独立 Web Admin；挑战与公告通过本机 Node API 在两个端之间共享。

```text
微信小程序模拟器 ─┐
                  ├─ 127.0.0.1:8790 ─ 本机 JSON 配置库
Web Admin 浏览器 ─┘
```

学生运动记录、精确轨迹和用户身份仍留在小程序本地 `wx storage`，不进入 Admin 配置库。

## 2. 实现内容

### Web Admin

- 运营概览：挑战数、已发布挑战数、公告数、操作记录数；
- 挑战管理：创建、编辑、发布/下架、删除；
- 公告管理：创建、编辑、发布/下架、删除；
- 最近配置操作记录；
- 表单校验、错误提示、空态和本机服务状态。

### 本机 API / 持久化

- `dev/admin-server.js`：Node 内置 HTTP 服务、静态后台与 Admin/公开 API；
- `dev/admin-store.js`：JSON schema 校验、本机持久化、原子文件替换和变更审计摘要；
- `utils/default-challenges.js`：小程序和后台共用默认挑战配置；
- 运行时数据路径：`data/local/ops-store.json`，已忽略 Git；数据文件在首次写入时创建；
- 服务绑定 `127.0.0.1:8790`，没有互联网账号/RBAC，不得暴露到局域网或公网。

### 小程序同步

- 个人中心新增“连接本机 Web Admin”开关，默认关闭；
- 开启后首页读取公告、活动页读取已发布挑战；
- 请求失败时使用本机 storage 缓存/默认数据；
- 不会同步运动记录、轨迹或用户身份。

## 3. 启动

在项目根目录运行：

```bash
node dev/admin-server.js
```

后台地址：

```text
http://127.0.0.1:8790/
```

启动本机 AI 复盘代理另见 README 的可选 AI 测试说明。两个服务分别运行；都只限本机开发环境。
