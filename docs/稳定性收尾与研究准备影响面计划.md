## 5. R2：AI 代理安全与成本保护方案

### 来源和 Host

- 保持 loopback-only；严格解析 Host，只允许本机名称 127.0.0.1/localhost 与当前监听端口；不使用字符串前缀匹配。
- 有 Origin 时，仅允许完整解析后主机为上述本机地址的 HTTP/HTTPS Origin；拒绝外部域名、伪装本机域名、null 和无效值。
- 没有 Origin 时，允许现有本机 wx.request/CLI 路径，但须通过 Host 检查；这是兼容策略，不是身份认证，也不能阻止本机恶意进程。
- 实际微信模拟器若发送其他合法来源，先记录最小必要的请求头特征并报告 Owner；不为了“跑通”恢复通配或默认放行所有微信域名。
- 仅对允许的 Origin 返回精确 CORS 值及 Vary: Origin；预检不触发上游，不计调用额度。来源拒绝返回 403，并保证上游调用数为 0。

### 轻量限额（拟议默认，待本计划确认）

- 单个代理进程最多 1 个进行中的模型请求，不排队；最多 5 个有效模型请求启动/滚动 60 秒。
- 超限返回 429 和适当的 Retry-After，不调用上游；健康检查、预检、拒绝来源及无效输入不消耗该额度。
- 调用已启动后，即使模型失败也计入启动额度；请求成功、上游错误和超时都必须释放并发槽。
- 使用进程内有界状态，服务重启后额度重置；不是跨机器限流，也不是服务商账单上限。
- 不增加新的用户账号、访问 Token、持久化调用日志或可扩展配置体系。
- 保持已有聚合输入、四字段输出、25 秒上游超时及客户端降级协议；默认不修改客户端 UI。
- 如需测试限额时间窗，使用测试时钟，不让测试等待整分钟、不新增生产测试开关。

### 密钥与真实模型

只用模拟上游和合成密钥完成自动化回归。旧 Key 是否撤销由 Owner 在服务商确认；不索取聊天中的密钥、不读写真实 .env。真实调用需要 Owner 另行确认新 Key 已轮换，并仅在当前进程环境注入；本轮默认不执行。

## 10. 数据流、权限与隐私风险

```text
小程序本地运动记录 → 六个聚合字段 → 本机 AI 代理
    → 来源/Host/输入检查 → 进程内限额 → 模拟上游（默认）
    → 已有四字段结果校验 → 小程序展示；错误 → 本地模板

本机 Web Admin ↔ 隔离测试 Admin API ↔ 合成挑战/公告 JSON
小程序测试环境 → 已发布配置；个人记录和 GPS 不进入 Admin 数据文件
研究材料 → 文档草案，无自动采集、无真实参与者数据流
```

来源校验不等于登录/RBAC；进程限额不等于总费用封顶；数据白名单不改变现有模型非医疗边界。日志和截图不得包含 Key、身份或完整轨迹。证据只保存必要、脱敏的结果；原始测试产物留在 Git 忽略目录，不提交。
