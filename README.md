# Campus Pulse · 校园燃动

> **中文名：校园燃动**
> **English name：Campus Pulse**
> **项目类型：微信小程序原生研究型原型**

## 如果你是人类，请看

### 1. 这个项目是做什么的

校园燃动不是普通的计步页面，而是一个用于研究“运动健康与社交激励交叉应用”的微信小程序原型，重点验证：

- 运动数据是否能帮助用户看见自己的进步；
- 周榜/月榜是否能形成适度的同伴激励；
- 线上挑战是否能提升参与意愿；
- 勋章和连续打卡是否能促进持续运动；
- 用户是否理解并愿意控制位置和打卡数据的可见范围。

当前功能包括：

- 首页：本周里程、目标进度、周/月趋势图和最近动态；
- 运动记录：演示模式、前台定位、时长、里程、配速、热量、轨迹、记录列表和详情；
- 榜单：周榜/月榜和本人高亮；
- 活动：挑战列表、详情、规则、进度、基于规则的本地推荐、加入/退出和邀请分享；
- 我的：累计统计、勋章墙、运动目标、隐私设置、本地记录删除和反馈草稿；
- AI 运动复盘：通过本机代理调用配置的 OpenAI-compatible 网关；失败时使用本地规则模板。
- 运营后台：独立 Web Admin 管理挑战和公告；本地 Node API 将已发布配置提供给开启本机后台的开发者工具模拟器。
- 分享：本地打卡预览和文案复制；当前不上传运动数据；
- 挑战推荐：基于本地规则生成推荐理由，不调用大模型。

### 2. 当前版本边界

当前版本是**研究展示版**。学生运动记录保存在小程序本地 `storage` 中；可选的本地运营后台使用本机 Node API 和被 Git 忽略的 JSON 配置文件：

- 只运行小程序时不需要 Node.js、npm、数据库或后端服务；
- 可选 Admin/AI 测试需要 Node.js，但不需要 npm 依赖；
- 不接入微信真实登录、云开发或生产数据库；
- 不启用后台持续定位；
- 不发送真实通知、奖励、积分或支付；
- 榜单同学、挑战参与人数和勋章奖励仍含演示数据；本机运营后台不是生产权限系统。

因此，它可以用于课程设计、毕业设计、答辩演示和可用性测试，但不能直接作为正式校园运营系统上线。

### 3. 手动部署与运行

安装：

- 微信开发者工具 Stable；
- Git（如果需要从仓库获取代码）。

本项目不需要执行：

```bash
npm install
npm run dev
```

```bash
git clone <你的仓库地址>
cd 1-2-3-4-1-api
```

如果代码已经在本地，则直接使用项目目录：


#### 3.3 导入微信开发者工具

1. 打开微信开发者工具；
2. 选择“小程序 → 导入项目”；
3. 选择项目根目录；
4. 当前测试 AppID 为：

```text
wxe9d70045c1937d39
```

5. 点击“编译”。

项目入口配置在：

```text

```

#### 3.4 运行演示模式

默认进入首页。测试运动记录时：

```text
首页 → 开始运动 → 保持“演示模式” → 开始记录
```

然后依次测试：

```text
开始记录 → 暂停 → 继续 → 结束并打卡
```

演示模式不需要定位权限，数据会保存到本地 storage。

#### 3.5 测试真实定位

在运动页关闭“演示模式”，再点击“开始记录”。小程序会请求前台定位权限。

注意：

- 当前只使用前台定位；
- 不要把本项目改成默认后台定位；
- 定位失败时可以切回演示模式；
- 真机测试需要检查微信权限和系统定位权限；
- 轨迹数据当前只保存在本地，不上传服务器。

#### 3.6 启动本机运营后台（可选）

运营后台是单独的 Web 端。本机 Node 服务只监听 `127.0.0.1:8790`，配置保存在 `data/local/ops-store.json`（已被 `.gitignore` 忽略），不包含学生运动记录。

在一个终端运行：

```bash
cd /Users/chou/Documents/Codex/2026-09-29/1-2-3-4-1-api
node dev/admin-server.js
```

在浏览器打开 `http://127.0.0.1:8790/` 管理挑战和公告。要让微信开发者工具模拟器读取已发布内容，在“我的 → 开发者工具运营后台”开启“连接本机 Web Admin”。服务关闭或连接失败时，小程序继续使用本地挑战数据。该服务无管理员账号，只能本机演示，**不要暴露到局域网或公网**。

#### 3.7 本地网络校验

当前版本没有后端域名，一般不需要配置合法域名。如果开发者工具因为本地调试提示校验问题，可以在本地开发设置中勾选：

```text
不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书
```

这只适用于本地开发，正式发布不能依赖该选项。

### 2. 启动和验证方式

只运行小程序时，不启动 Node 后端；在微信开发者工具导入项目并编译即可：

```text
微信开发者工具 → 导入项目 → 选择项目根目录 → 编译
```

自动化回归测试（纯 Node.js 内置测试框架，无需安装依赖）：

```bash
node --test tests/*.test.js
```

可以执行的静态检查：

```bash
for f in app.js pages/*/*.js; do node --check "$f"; done
```

JSON 检查：

```bash
python3 - <<'PY'
import json
from pathlib import Path
for name in ['app.json', 'project.config.json', 'sitemap.json']:
    json.loads(Path(name).read_text())
    print(name, 'ok')
PY
```

WXML 检查重点：

- 不要写 `{{value.toFixed(2)}}`；
- 不要写 `{{value.slice(0, 1)}}`；
- 不要在 WXML 中调用任意 JavaScript 方法；
- 复杂计算在页面 `.js` 中完成后再通过 data 提供给 WXML；
- 插值括号必须成对出现。

### 3. 页面操作方法

#### 首页

- 查看本周里程和目标进度；
- 点击“开始运动”进入运动页；
- 点击“加入挑战”进入活动页；
- 查看最近运动动态。

#### 运动页

- 默认使用演示模式；
- 开始后会生成演示坐标；
- 第一个坐标只更新地图中心；
- 至少两个有效坐标后才绘制 polyline；
- 可以暂停、继续和结束；
- 结束后保存本地记录。

#### 榜单页

- 支持本周榜和月度榜切换；
- 领奖台和完整榜单数据由页面 JS 预先整理；
- 不要在 WXML 中调用 `.slice()` 或其他方法。

#### 活动页

- 加入挑战会保存到本地 storage；
- 已加入挑战可以退出；
- 进度文字和进度条宽度由 JS 计算；
- 不要把客户端演示数据当作服务端可信排名。

#### 我的页

- 查看累计里程、运动次数和勋章；
- 在“开发者工具运营后台”开启本机 Admin 配置同步（仅模拟器）；
- 设置榜单公开、打卡可见和提醒开关；
- “删除本地运动记录”只清除当前设备的演示数据。

### 4. 本地存储约定

```text
campus-fit-records       本地运动记录
campus-fit-challenges    本地挑战状态
campus-fit-settings      本地隐私和提醒设置
```

不要将这些本地 key 误认为后端数据表或正式 API 契约。

### 5. 调试顺序

遇到问题时按以下顺序处理：

1. 读取开发者工具中的第一条真正错误；
2. 确认是否是 WXML 表达式错误；
3. 检查页面 JS 是否把计算字段放入 `data`；
4. 检查 `wx:for`、`wx:key` 和数据是否为空；
5. 运动页检查定位状态、点位数量和 polyline 数据；
6. 检查 `app.json` 页面路径和权限声明；
7. 清缓存后重新编译；
8. 记录实际错误、修改文件和验证结果。

以下提示通常不是主要业务错误：

```text
resource ... was preloaded ...
```

### 6. 地图调试规则

地图折线必须满足：

```js
[
  {
    points: [
      { latitude: 31.2304, longitude: 121.4737 },
      { latitude: 31.23055, longitude: 121.47388 }
    ],
    color: '#e36b3d',
    width: 5
  }
]
```

注意：

- `points` 至少包含两个有效点；
- `latitude` 和 `longitude` 必须是有限数字；
- 第一个点不创建折线；
- 不要传入带有 `paths` 的自定义错误结构；
- marker 如缺少图标资源，优先暂时使用空数组排除干扰。

- 先读 `skills/project-safety-boundary/SKILL.md`；
- 高风险改动先更新影响面计划；

- 不修改真实微信 Secret、证书或生产配置；
- 不启用后台定位；

- 最终必须说明已验证事实、未验证部分和剩余风险。

### 8. AI 完成标准

一次修改只有在以下内容都说明后才算完成：

- 修改了哪些文件；
- 修改解决了什么问题；
- 是否影响数据、定位、权限或隐私；
- 执行了哪些静态检查；
- 是否在微信开发者工具中实际编译；
- 是否完成页面人工验收；
- 是否接触真实后端、数据库或 Secret；
- 哪些内容仍需人类确认。
